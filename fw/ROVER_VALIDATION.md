# 로버 검증 환경 — fw/ 를 로버 기준으로 잰다

UAV(상공 관측·미세도플러 liveness)와 **별도**로, `fw/`(C99 결정 executive)의 **상태추정·고장대응·
안전전이 척추**를 로버 물리·센서오차·고장에서 잰다. 구조는 sar/ivv(심판↔SUT 분리)와 동형:
**시뮬레이터가 로버 물리·가상 센서·고장을 생성**하고, **`fw_agent_step`(실 libfw.so, ctypes)이
그 입력으로 행동을 결정**한다. 정책 C 코드는 손대지 않는다.

## 1. 구조 (정책과 시뮬 분리)

```
로버 물리(skid-steer 운동학·바퀴 슬립)     ← rover/rover_sitl.py Rover
   → 센서 어댑터/고장 주입(엔코더·IMU·GPS·장애물·가짜표적; 잡음·지연·누락·고착)
   → fw_bridge_step(실 libfw.so)  Estimator→Evidence→Safety→BT→Arbiter→SafetyFilter
   → Action 어댑터(APPROACH/AVOID/RELOCALIZE/RETURN/EMERGENCY → v,ω 명령)
   → 로버 구동기(명령 적용 → 다음 물리 상태)
```

fw 는 모터를 직접 안 돌린다 — **행동을 고르고**, 어댑터가 그것을 바퀴 명령으로 옮긴다. ROS2/Gazebo 를
써도 정책은 이 C99 라이브러리로 유지되고, 시뮬은 외부 테스트 하네스일 뿐이다(HW_BRINGUP.md 의 HAL 계약).

## 2. 실행

```
python3 rover/rover_sitl.py        # R-01..R-08 표(고정 seed)
python3 tests/test_rover_sitl.py   # 회귀: fw 응답 차별화·알려진 gap 정직 확인
```

## 3. R-01..R-08 결과 (실측, seed=7, L2 운동학-경량)

지표: RMSE=참 위치오차 RMS(m, 주기 GPS 사이 추측항법 표류 포함) · RELOC=RELOCALIZE 스텝수 ·
가짜확정=목표 없이 확정(오확정) · 도달=목표 1.5 m 내 진입.

| 시나리오 | 결과 | fw 응답(정직 판정) |
|---|---|---|
| R-01 평탄·정상 | 도달 t=75 | **척추 정상** — 목표 접근·도달 |
| R-02 바퀴 미끄러짐↑ | 도달 t=115(느림) | 슬립이 진행을 늦춤; 주기 GPS 로 복구해 결국 도달 |
| R-03 엔코더 고착 | 도달 t=75·RMSE 0.64·응답 0 | **GAP** — fw 는 고착 센서 판별이 없다(fault_test stale gap 동뿌리) |
| R-04 IMU 편향 | 미도달·RMSE 0.65 | 자세오차→위치오차↑; 편향이 도달을 막음 |
| R-05 GPS 지연·누락 | 미도달·**RELOC 88** | **척추 정상** — 측위 신뢰 무너지면 RELOCALIZE(추측항법 위 전진 금지) |
| R-06 경로 암석 | 암석 0.8 m 통과·AVOID 0 | fw AVOID 는 collision≥0.8(~0.5 m) **근접 반사** — 경로 회피는 항법 몫(fw 밖) |
| R-06b 암석+모션층 회피 | 암석 1.6 m 우회·도달 t=81 | **행동 제어=모션 층** — 같은 fw 행동인데 퍼텐셜필드가 부드럽게 우회(§4.5) |
| R-07 통신 단절 | 도달 t=75 | **fw 밖** — 링크 실패안전은 RTA/RTL(HW_DESIGN §3.3), fw 입력 아님 |
| R-08a 순간 가짜 | 가짜확정 **아니오** | **척추 정상** — 센서독립·튐 → CMPC·시간이 거른다 |
| R-08b 지속 가짜 | 가짜확정 **예** | **GAP** — co-locate·고정 가짜는 시간·운동 통과 → 생체(UAV 전용) 없이 확정 |
| R-09 도랑 빠짐(복구 없음) | 이동 3.8 m·복구 0·미도달 | **fw 밖** — fw 는 immobilization(명령↔실제 이동 불일치)을 모른다 → 전진만 명령해 갇힘(§4.5) |
| R-09b 도랑+모션층 복구 | 이동 15.9 m·복구 1·도달 t=90 | **행동 제어=모션 층** — VO 로 헛돎 검출→후진·우회 복구, **fw 정책 불변**(우세행동 동일)(§4.5) |

**요지(경계지도와 일치):** fw 의 안전 척추(측위 상실→RELOCALIZE, 순간 가짜 거부, 목표 도달)는
로버에서도 성립한다. **로버에서도 같은 두 gap** 이 드러난다 — 고착 센서(R-03)와 지속 가짜(R-08b).
둘 다 UAV 에서 찾은 그 gap(정지·고착·전-서명)과 **동뿌리**이며, 해법도 같다: liveness/서명 채널.
단 로버에는 UAV 의 미세도플러 liveness 가 안 붙으므로 R-08b 는 여기서 열린 채다(정직).

## 4. fw 밖(경계) — 로버에 필요하지만 fw 가 안 하는 것

- **경로계획 장애물 회피**: fw AVOID 는 임박 충돌 반사(collision≥0.8)일 뿐. 주행 중 암석 우회는
  **항법층**(PX4/nav·geofence) 몫. fw 는 belief·안전행동만 고른다.
- **목표 waypoint tracking·slip 보상 주행**: fw 는 SAR 탐색 executive라 goal-seek 주행 제어가 없다.
  이 하네스는 어댑터로 근사할 뿐 — 실 로버는 항법층이 담당.
- **통신 실패안전(R-07)**: 링크 계층·RTA. fw 입력에 comms 항이 없다.
- **구동계·stale 센서(actuator_ok)**: `fw_bridge_step` 이 안 받는다 → 네이티브 `fault_test.c`(#5·#6)가
  이미 다룬다(구동계 고장→ACT_NONE, stale→미검출 GAP).
- **immobilization(도랑 빠짐, R-09) 검출·복구**: 명령↔실제 지면속도 불일치는 fw 입력에 없다. 검출·복구
  (후진·우회)는 **모션 층**에 뒀다(R-09b, §4.5) — fw 결정론·인증 표면 불변.

## 4.5 행동 제어(모션 층) vs fw(행동 모드) — 조향·회피·복구는 어디에 있나

**fw 는 "무엇을 할지"(이산 행동 모드: SEARCH/APPROACH/AVOID/…)만 고르지, "어떻게 움직일지"(연속
조향·속도)는 안 정한다.** fw Action → (v, ω) 변환이 **행동 제어(모션 층)**이고, 실 HW 에선 PX4/항법이
그 자리다(`rover_sitl.action_to_cmd`, `sar/HW_DESIGN.md` §2).

- **장애물 방향 트는 회피**: R-06 은 fw 만으로 암석을 0.8 m 스쳐 지난다(fw AVOID 는 collision≥0.8
  근접 반사일 뿐). R-06b 는 **모션 층에 퍼텐셜필드 국소 회피**를 켜 같은 fw 행동인데 암석을 1.6 m 로
  **부드럽게 우회**하고 도달한다. → **조향·경로 회피는 fw 가 아니라 모션/항법 층**이다(어댑터에 있음).
- **도랑에 빠짐(immobilization, R-09 vs R-09b)**: 명령은 전진인데 실제로 못 움직이면(헛돎) — fw 는 이걸
  **모른다**. fw 입력엔 "명령 속도 ↔ 실제 지면 속도" 불일치 신호가 없어, 위치추정이 성하면(GPS 보정)
  계속 전진만 명령한다. 도랑 물리도 정직히 방향의존이다: **안에서 전진하면 먼 벽에 처박혀 헛돌지만,
  후진은 들어온 쪽 접지로 빠져나올 수 있다(로킹 탈출)**. 그래서 전진만 아는 fw(R-09)는 이동 3.8 m 뒤
  **갇힌 채 미도달**(복구 0)이다.
  - **복구를 어디에 두나 — 모션 층에 뒀다(설계 결정).** immobilization 판별·복구는 fw 에 없는 새 축이라,
    (a) **모션 층**에 검출+복구 거동을 넣거나 (b) fw 에 새 FDIR 이벤트를 추가(설계 변경)하는 두 길이 있었다.
    **fw 의 결정론·인증 표면을 안 건드리려고 (a) 를 택했다** — 실 HW 의 PX4 failsafe 와 같은 자리.
  - **R-09b(모션층 복구)**: 모션 층이 **시각오도메트리(VO, 바퀴 인코더와 독립)** 로 "명령했지만 안 움직인"
    스텝을 세어 헛돎을 검출(창 8스텝에 ≥3) → **후진으로 탈출 → 도랑 옆 우회 waypoint 로 주행**(단순 후진·선회만으론
    도랑이 목표 직선상이면 퍼텐셜필드 국소최소로 되빨려 든다). 결과: 이동 15.9 m·**도달 t=90**·복구 1회.
    **fw 정책은 불변**(R-09·R-09b 우세행동 동일 INSPECT) — 복구는 어댑터가 했지 fw 가 아니다.
  - SPOC-Lite(지형 위험 분류)는 **빠지기 전에** 위험 지형을 피하는 입력을 준다(collision_risk 류) — 사전 회피,
    이건 사후 복구. `tests/test_rover_sitl.py::test_immobilization_recovery_lives_in_motion_layer_not_fw` 가
    이 R-09 vs R-09b 대비(fw 불변·모션층만으로 탈출)를 잠근다.

즉 로버의 "방향 트는 제어·도랑 탈출"은 대부분 **모션/항법 층**의 일이고, fw 는 그 위에서 모드를 고른다.
이 분리가 곧 HW_BRINGUP.md 의 칩 분담(정책 MCU=fw, 비행/구동제어=PX4)과 같다.

## 5. 정직 — 이 환경의 충실도

- **L2 운동학-경량.** 평면 skid-steer + 단순 슬립일 뿐, **토양-바퀴 동역학(마찰·침하·slip/sinkage)이
  아니다.** 접촉·마찰 파라미터를 검증하지 않았다. 절대 RMSE 수치는 이 단순 모델의 것이다.
- 결론은 **시나리오별 차별화와 방향성**(R-05 측위상실→RELOC, R-08 순간거부/지속확정, R-03 무검출)
  에서 오지, 절대수치에서 오지 않는다. `tests/test_rover_sitl.py` 가 그 차별화·gap 을 잠근다.

## 6. 고충실도 사다리 (L3+) — 이 컨테이너 밖

이 컨테이너엔 ROS2/Gazebo 가 없다. 다음 계단은 외부 환경에서:

| 도구 | 용도 | 주의(정직) |
|---|---|---|
| **Gazebo Harmonic + ROS 2** | 물리 시뮬·센서/제어 인터페이스, skid-steer 예제. fw 를 C 라이브러리로 링크(정책 유지) | 기본 모델이 실 토양 침하·슬립을 정확히 재현하진 않음 — 접촉·마찰 파라미터 검증 필요 |
| **NASA/JPL ROAMS** | 바퀴-토양 상호작용·slip/sinkage **기준값** 참고 | 공개 소개만으로 즉시 설치 가능한 완전 오픈소스라 단정 불가 — 접근성·의존성 먼저 확인 |
| **NASA JPL Open Source Rover** | rocker-bogie·차동회전 **실물 기준 형상**(기구학) | 하드웨어 설계 공개 ≠ 완성도 높은 동역학 시뮬 제공 |
| **NASA SPOC-Lite** | 모래지형 위험 분류 → 주행 위험을 정책 입력(collision_risk 등)으로 | 지형 분류 기능이지 전체 동역학 시뮬 아님 |

권장 순서: **Gazebo Harmonic 에 이 fw C 라이브러리 링크(정책 통합)** → ROAMS 로 slip/sinkage
검증 기준 설정 → SPOC-Lite 를 지형위험 분류 참고 → 재현되면 크로스컴파일·타이밍·HAL·HITL(HW_BRINGUP.md).

## 7. 범위 — UAV 와 분리

로버 시뮬은 fw 의 **상태추정·고장대응·행동선택**을 잰다. **UAV 의 상공 관측·미세도플러 liveness
판별은 직접 입증하지 않는다** — 그 둘은 별도 실험(sar/ivv·liveness_ref)으로 유지한다.
