# 보고서 PDF 구성 정책 reportkit

검색어: 보고서 PDF 정책 · 보고서 구성 정책 · PDF 구성 · 기술 보고서 PDF · 프로토타입 보고서 PDF · 보고서 정책 · 시각화 · 회로도 · 시스템 아키텍처 · 수식 · report_pdf · reportkit · POLICY.md

사용자(2026-09-29): "PDF 를 구성하면서 사용한 시각화 자료, 회로도, 시스템 아키텍처, 수학/물리/화학 설명 등 PDF 구성 정책을 채택하려 한다."
-> reportkit/POLICY.md 로 규칙화, reportkit/check.py 가 강제, 도구 report_pdf(markdown).

절 순서: 표지(모델 출력·미검증 경고) -> 요약(수치+출처, 찾은 것, 하지 않은 것) -> **단점(좋은 점보다 먼저)** -> 선행연구(+조사 한계) -> 원리·이론(주·부반응식, 메커니즘, 서술자) -> 수학 모델(식+파라미터 출처 [A]/[L]/[C]/[M]) -> 설계·사양(표, 안전 계층, 가로 쪽 도면+표제란) -> 제작 레시피(분량·온도·시간·QC 합격 기준) -> 취급·안전 -> 결과(번호 그림, 모델 검사 표) -> 대책(구분+정량 비교) -> 실험·검증 청사진(합격 기준+교체하는 파라미터) -> 응용(맞지 않는 곳도) -> 증명한 것/못 한 것 -> 참고문헌(확인 수준 [전문]/[초록]/[목록]/[조각]/[기억]).
기계 검사: 필수 절, 참고문헌 확인 수준, 그림 캡션, 요약 수치 출처(요약 절 본문만), 과장 어휘, [verify]. 위반이면 PDF 를 안 만든다.
이점을 쓸 때: 지금 사실인지부터(가격!), 물리 원인으로 분해, 같은 성능·같은 투입량 두 표, 깨지는 조건을 숫자로.
빈 틀: reportkit/template.md. 수식 KaTeX(동봉), 그림 ![캡션](경로), 도면 !drawing[캡션](경로).
