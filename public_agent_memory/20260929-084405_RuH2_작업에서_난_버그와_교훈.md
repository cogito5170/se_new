# RuH2 작업에서 난 버그와 교훈

RuH2-P1(Ru 수소 전극 Ni-H2 배터리) 작업 중 실제로 난 것. 비슷한 설계·렌더 작업에 그대로 적용된다.
1. 사양이 GDE 를 unit 당 한 장만 셌다(back-to-back 은 두 장) -> 면적·Ru 량 절반. 도면 에이전트가 잡음. 도면·모델·3D 가 한 사양 파일을 읽으면 서로 교차 검증된다.
2. 방전 말단 Ni 공급 한계 누락 -> 1.0 V 종지 전에 역전. 웹 시뮬레이터가 정상 시나리오에서 '트립'을 띄워 드러남. 이상 신호를 무시하지 말 것. tests/test_ruh2.py 가 붙든다.
3. 3D: 라벨이 부품을 가림 -> 좌우 열 + 지시선(callout). 과노출 -> exposure·envMapIntensity 낮춤. 나눔 폰트에 ₂·⁻·− 글리프 없음 -> <sub>/<sup>, '-'. 실제 치수로 모델링하고 도면과 같은 형태로(가로->세로 용기 수정).
4. 영상: swiftshader 로 1280x720 30 fps 70 s 에 4 코어 병렬 약 40 분. 장면을 결정적(renderAt(t))으로 만들고 구간 분할 렌더 후 ffmpeg concat. 디스코드 한도 때문에 960px·crf 26.
5. 칼만 필터를 손 Q 로 넣었더니 더 나빠짐 -> 학습 데이터로 Q 추정, 그래도 이득 없음을 그대로 보고.
6. pgrep -f 패턴이 내 셸 명령줄에 걸려 셸이 죽음 -> PID 먼저 확인. 오래 사는 부모의 끝난 자식은 좀비라 kill(pid,0) 이 성공 -> /proc/<pid>/stat 상태로 판정.
7. 글자만 보는 검사 거짓 초록: 보고서 '요약' 검사가 다음 절 단어로 통과 -> 절 단위로. 옳은 틀을 망가뜨려 빨개지는지 보는 테스트(test_reportkit).
8. 이 환경: 출판사·PMC 사이트 차단 -> 인용은 [조각] 표시. CDN 차단 -> three.js·Chart.js·KaTeX 를 저장소에 동봉. pypdf import 가 패닉 -> 쪽 수는 바이트로 셈.
