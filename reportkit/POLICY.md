# 기술 보고서(PDF) 구성 정책

**출처.** RuH2-P1 프로토타입 보고서(2026-09-29, `ruh2/`)를 만들면서 쓴 구성을 규칙으로 옮겼다.
그 보고서는 사용자가 두 번 고쳐 달라고 한 끝에 나온 형태다. 첫 요청("청사진·반응식·원리·수학 공식·물리·화학
이론·실험·검증 시 필요한 모든 것")과 둘째 요청("단점을 명시하고, 그럼에도 Pt 대신 Ru를 쓰는 이점을 비용과
반응도로, 산화·자가방전 방지 방법론까지")이 이 정책의 뼈대다.

**강제 위치.** `reportkit/check.py` 가 아래 규칙 중 **기계로 볼 수 있는 것**을 검사한다. 위반이 있으면
`reportkit.build` 는 PDF 를 만들지 않는다(`strict=False` 로만 우회되고, 우회해도 위반 목록이 보고서
첫 쪽에 빨간 상자로 찍힌다). 사람만 볼 수 있는 규칙은 그렇다고 적어 두었다 -- 게이트가 초록이라고
보고서가 옳은 것은 아니다(CLAUDE.md '이 게이트들이 **못** 잡는 것').

## 1. 절의 순서 (필수 — 기계 검사)

| # | 절 | 무엇을 쓰나 | 검사 키워드 |
|---|---|---|---|
| 0 | 표지 | 제목, 문서번호·rev·날짜, 한 줄 사양, **"모델 출력 · 실측 아님 · 설계 미검증"** 경고 상자 | (표지는 자유) |
| 1 | 요약 | 핵심 수치 표(값 + 출처 표시), **찾은 것 3개**, **하지 않은 것** | `요약` |
| 2 | 단점 | 단점 표(근거·크기·의미). 좋은 점보다 **먼저** 둔다 | `단점` 또는 `한계` |
| 3 | 선행연구 | 층위별 가장 가까운 선행연구, 새것/새것 아님, **조사 한계** | `선행` |
| 4 | 원리·이론 | 반응식(주·부반응), 메커니즘, 서술자(예: ΔG), 계산 방법 | `원리` 또는 `이론` |
| 5 | 수학 모델 | 식 + 기호 설명 + 각 파라미터의 출처 표시 | `모델` 또는 `수식` |
| 6 | 설계·사양 | 사양 표, 안전 계층, 회로·기구 도면(가로 쪽) | `설계` 또는 `사양` |
| 7 | 제작 방법 | 레시피(분량·온도·시간·QC 합격 기준), 조립 순서 | `제작` 또는 `레시피` 또는 `방법` |
| 8 | 취급·안전 | 한계값 표 + 이유, 위험물·압력·전기 | `안전` 또는 `취급` |
| 9 | 결과 | 그림(번호·캡션), 표, **모델 검사 표**(§4) | `결과` |
| 10 | 대책 | 약점마다 대책 표 + 정량 비교(가능하면) | (단점이 있으면 권장) |
| 11 | 실험·검증 청사진 | 단계 · 대상 · 방법 · **합격 기준** · **교체하는 모델 파라미터** | `실험` 또는 `검증` |
| 12 | 응용 | 맞는 분야와 **맞지 않는 분야** | `응용` |
| 13 | 증명한 것 / 못 한 것 | 두 목록을 나란히 | `증명` 또는 `하지 않은` 또는 `못 한` |
| 14 | 부록·참고문헌 | 파라미터 표, 실행 방법, 확인수준 붙은 참고문헌 | `참고문헌` |

## 2. 근거 표시 (기계 검사)

- **참고문헌마다** 확인 수준을 붙인다: `[전문]` 본문을 읽음 · `[초록]` · `[목록]` · `[조각]` 검색 요약만 · `[기억]` 확인 안 한 기억.
  CLAUDE.md '읽지 않은 것을 인용하지 않는다' 의 표면 형식이다. `[verify]` 같은 얼버무림은 위반이다.
- **파라미터마다** 출처를 붙인다: `[A]` 가정 · `[L]` 문헌 · `[C]` 본 작업 계산 · `[M]` 실측.
- **요약의 수치**는 어디서 왔는지(모델/실측/문헌) 같은 문단이나 표에 적는다.

## 3. 시각 자료 (일부 기계 검사)

- 그림은 **번호와 캡션**을 가진다(`그림 N.`). 캡션은 "무엇을 보라" 를 한 문장으로 쓴다. 캡션 없는 그림은 위반.
- **회로도·기구도·블록도**는 가로 A4 한 쪽에 하나. 도면마다 표제란(도면번호, rev, 날짜, 척도, **"설계 제안 — 미검증"**).
- 도면의 모든 수치는 단일 사양 파일(`spec.py` 같은 것)에서 계산한다. 그림에 숫자를 손으로 쓰지 않는다.
- 차트: 한 축(이중 y축 금지 · 불가피하면 명시), 범례, 단위, 수치 라벨은 선택적으로. 한글 폰트는 나눔.
  `−`(U+2212)·아래첨자 글리프가 폰트에 없으면 두부 글자가 된다 — `-` 와 `<sub>` 를 쓴다.
- 3D 렌더·영상 스틸은 **실제 치수**로. 라벨은 부품을 가리지 않게 좌우 열 + 지시선으로.
- 수식은 KaTeX(저장소에 동봉, 인터넷 불필요). 반응식은 `\mathrm{}`, 표 안의 짧은 식은 인라인.

## 4. 재고 나서 보고하기 (사람 검토 + 일부 기계 검사)

CLAUDE.md '재고 나서 보고하기 전에' 의 네 가지를 보고서 안에 **표로** 남긴다(모델 검사 표):

| 검사 | 결과 | 해석 |
|---|---|---|
| 질량/에너지 수지 | 잔차 | **같은 식을 적분한 것이면 구현 검사일 뿐이라고 적는다** |
| 닫힌 식 대조 | 값 vs 값 | 정의상 일치하는 것은 "정의상" 이라고 적는다 |
| 시간 간격 수렴 | 차이 | |
| 이식 대조 (JS↔Python 등) | 최대 차 | |

- 주장마다 **깨지는 조건**을 적는다("이 결론이 깨지는 조건"). 못 적으면 주장이 아니라 광고다.
- 과장 어휘(`세계 최초`, `획기적`, `혁신적`, `완벽`)는 위반.
- 부정 결과를 지우지 않는다. 고친 버그는 "첫 판은 이랬고 이렇게 고쳤다" 로 남긴다.

## 5. 이점을 쓸 때 (사람 검토)

사용자가 "그럼에도 X를 쓰는 이점" 을 물으면:
1. **지금 사실인지부터** 확인한다(예: 2026-09 Ru 가격은 Pt 와 질량당 거의 같다 → "싸다" 는 틀림).
2. 이점을 **물리적 원인**으로 분해한다(예: 전류/질량 = j₀ 비 × 밀도 역비 = 2.86 × 1.73 ≈ 5).
3. 같은 성능 기준 비교표 + 같은 투입량 비교표를 둘 다 둔다.
4. 깨지는 조건(재현 실패, 열화, 가격 변동, 규모)을 숫자로.

## 6. 대책을 쓸 때 (사람 검토)

- 대책을 **시스템 · 회로 · 펌웨어 · 셀 설계 · 운용 · 공정 · 소재**로 구분한다.
- 모델로 돌릴 수 있으면 대책별 효과를 **같은 시나리오**에서 비교한 막대그림을 둔다.
  (RuH2 에서 얻은 교훈: 소재 대책만으로는 막지 못하는 경우가 있었다 — 그것도 그대로 적는다.)

## 7. 제작 규칙

- 한 파일(사양) → 모델 → 그림 → 보고서 순서로 **재생성 가능**해야 한다. 손으로 고친 그림 금지.
- 산출물은 무시되는 자리(`inbox/…`)에 쓴다. 검사·빌드가 원장을 더럽히지 않는다.
- PDF 크기는 디스코드 한도(약 10 MB) 아래. 큰 도면 PNG 는 JPEG 로 줄여 싣는다.
