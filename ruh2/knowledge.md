# RuH2-P1 작업 기록 — 요청, 해석, 결정, 수치, 교훈 (2026-09-29)

같은 종류의 요청(촉매·배터리·수소·전기화학 장치 설계 + 보고서 + 3D + 영상)이 오면 **이것부터 읽고**
`ruh2_battery` · `ruh2_make` · `report_pdf` 도구를 쓴다. 처음부터 다시 짓지 않는다.

## 1. 요청이 어떻게 흘렀나 (사용자 말 그대로 요약)
1. "Ru 기반 수소 시스템 연구·제작 지침서"(Ru 촉매 → 전기화학 → V/I/T/EIS → 상태추정)를 SE agent 로 시행,
   **저장소는 읽기만**, 결과는 **3D 렌더**로. → 수전해 셀 디지털 트윈(0-D 모델, EIS, C 펌웨어 lock-in, 센서 ablation, GPAW DFT).
2. "하드웨어 도면·handling parameter·Ru recipe·이론·원자 반응 3D 영상·반응식·수식·실험/검증 청사진·스펙·응용 분야,
   reference 포함 최종 PDF, 실행 시뮬레이션, **mp4**. 3D 라벨이 소자를 가리고 가독성·사실감 부족. **Ru 기반 수소 배터리**를 만들려 한다."
3. "Ru 가 수소를 저장하나, 촉매인가?" → **촉매**. 64.5 mg Ru 가 표면 전부 H 를 잡아도 0.32 mmol H₂ = 1 Ah(18.7 mmol)의 1.7 %.
   선택지 A(Ni–H₂ 배터리)·B(LOHC)·C(NH₃)·D(NaBH₄) 중 사용자가 **A** 선택.
4. "실제로 만들 수 있나, 이점은?" → 가능(사람이 실험실에서). 3단계: 비커 반전지 → 개방형 풀셀 → 압력 셀.
5. "PDF 에 단점 명시 + 그럼에도 Pt 대신 Ru 의 이점(비용·반응도) + 산화·자가방전 방지 방법론."
6. "세션을 SE 의 RAG 에 저장" → "설계에 쓴 tool 을 배선하라" → "PDF 구성 정책을 채택하려 한다". → `ruh2/` · `reportkit/` · 도구 3개.

## 2. 해석과 결정
- "Ru 기반 수소 배터리" = **Ni–H₂ 배터리의 수소 전극 촉매를 Pt 대신 Ru/C** (NiOOH | 30 wt% KOH | Ru/C GDE, 316L 압력용기).
  가장 선행연구가 많고 Ru 가 전극 반응에 직접 들어가는 구조라서. 다른 해석(URFC, 금속수소화물)은 선택지로만 제시.
- 셀: 1.0 Ah, 공칭 1.25 V, back-to-back 4 unit, Ø46 mm, **Ru/C 8장 128.9 cm², Ru 64.5 mg**, 자유기체 132.9 mL,
  예충전 1.0 → 완충 4.48 bar abs. **저압 설계**(운전 ≤5, 차단 6, 릴리프 8, 파열판 12, 설계 20, 내압 30 bar).
- BMS: STM32G474, 10 mΩ+INA240A2, 압력 0–10 bar, NTC×2, H₂ 센서, **비교기 4채널 → 래치 → 차단, MCU 해제 불가**.
- 세로형 용기(윗덮개에 포트·피드스루). 3D 는 처음 가로형이었다가 도면(M-001)에 맞춰 바꿨다.

## 3. 핵심 수치 (모두 가정 파라미터 모델의 출력 — 실측 아님)
- C/2, 25 °C: 출력 0.956 Ah, 쿨롱효율 86.9 %, **왕복 에너지효율 78.6 %**, 최대 4.40 bar, 27.3 °C, Ru 과전압 0.7 mV.
- **Ru 의 이점은 효율이 아니라 촉매량**: 같은 담지량이면 Ru·Pt 효율 차 0.25 %p. 전류/질량 = j₀비 2.86 × 밀도역비 1.73 ≈ 5.
  같은 성능 Ru 0.5 mg/cm² $3.55 vs Pt 2.48 mg/cm² $18.31 (−81 %). **2026-09 가격은 Ru≈Pt(질량당)** — "Ru 가 싸다" 는 틀림.
  깨지는 조건: j₀비 불재현(→ 이득 ~42 %), Ru/C 400 분 −56.5 % 열화 보고, 가격 추가 상승, 1 Ah 에선 촉매비 ≪ 용기.
- 산화(>0.4 V vs RHE): 예충전 / 0.9 V 래치 / 압력 하한 정지 **하나만 있어도** Ru 100 % 유지. 내산화 소재(Pt 도핑, 개시 0.8 V)**만으로는 못 막음**.
- 자가방전 72 h: 25 °C 18.3 % · 10 °C 5.9 % · 자유기체×2 12.2 % · 50 % SOC 7.0 % · 친수성 분리막(가정 ½) 10.0 % · 조합 1.9 % · 40 °C 40.5 %.
- DFT(GPAW PBE, 350 eV, 4×4×1, 2×2 4층): ΔG_H* Ru(0001) −0.37(fcc)/−0.34(hcp), 대조 Pt(111) −0.21 (문헌 −0.09 → 설정 오차 ~0.1 eV).

## 4. 실제로 난 버그와 교훈
1. **spec 이 GDE 를 unit 당 한 장만 셌다**(64.5→128.9 cm²). 도면 서브에이전트가 잡았다. 교훈: 도면·모델·3D 가 **한 사양 파일**을 읽게 하면 서로 교차 검증된다.
2. **방전 말단 Ni 공급 한계 누락** → 1.0 V 종지 전에 역전. 웹 시뮬레이터가 표준 사이클에 "트립" 을 띄워 드러남.
   교훈: 결과 화면의 이상 신호(정상 시나리오의 트립)를 무시하지 말 것. 고친 뒤 영상 재렌더.
3. 첫 영상 렌더: 과노출(원자가 흰 구슬), 카메라가 H* 를 가림, 나눔 폰트에 ₂·⁻ 글리프 없음(→ `<sub>`), 페이지 로드 순서 버그(PARTS 가 만들어지기 전 객체 참조).
4. **칼만 필터가 오히려 나빠짐**(첫 판 Q 를 손으로) → Q 를 학습 셀에서 추정. 그래도 이득은 시드 수준 — 그대로 보고.
5. 고전류 EIS 에서 R_ct 는 j₀ 와 무관(Tafel 영역) → 열화가 반원 크기로 안 보임. 지침서 가정이 틀린 자리.
6. `pgrep -f` 패턴이 내 셸 명령줄에도 걸려 셸이 죽음 → PID 확인 후 kill. 좀비 자식은 `kill(pid,0)` 이 성공 → /proc 상태로 판정.
7. 보고서 요약 검사가 '요약' 뒤 3000 자를 봐서 다음 절 단어로 거짓 통과 → 절 단위 검사로 고침(test_reportkit).
8. 이 컨테이너에서 pypdf import 가 cryptography 패닉(BaseException). CDN·출판사 사이트 차단 → 라이브러리 동봉, 인용은 [조각].

## 5. 다시 할 때
- 분석 글: `ruh2_battery(무엇=사이클|ru_pt|산화대책|자가방전대책|실험설계|사양|지식)`.
- 산출물: `ruh2_make(보고서|도면|그림|웹|영상|영상상태)` — 영상은 배경(수십 분), 끝났다고 말하기 전에 '영상상태'.
