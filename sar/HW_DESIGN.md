# SAR UAV 하드웨어·통신 설계 (지도+red spot → 탐색 → 구조자 확인)

임무: 운용자가 지도(네이버/카카오/구글)에서 **red spot**을 찍고 "그 주변 실종자 탐색"을 명령하면,
UAV가 그 좌표로 가 능동탐색하고, 탐지 결과(사진·GPS·신뢰도)를 **Discord 봇(수신기)**으로 돌려보낸다.

이 문서는 그 시스템의 센서·연산·통신·안전을 정한다. 소프트웨어 정책 코어(`policy_core/`)와의
분담을 명시한다: **perception(보는 것)은 학습·NPU, 정책(판단)은 결정적·MCU, 안전(RTA)은 링크 무관.**

---

## 0. 한눈에 — 데이터 흐름

```
 [운용자]                  [지상국 GCS]                    [UAV]
 Discord 채널   command    인터넷↔봇 브리지   MAVLink/LTE   ┌─────────────────────────┐
 !search <lat,lon> ──────▶ 명령 검증·승인 ───────────────▶ │ 비행 MCU (PX4/STM32H7)  │
 red spot                                                   │  · policy_core.c (결정)  │
                                                            │  · RTA/geofence (안전)   │◀─ GNSS/IMU/고도계
 Discord 카드   downlink   봇이 게시            LTE/radio    │  · 웨이포인트 → 비행제어  │
 [탐지 썸네일   ◀────────── 탐지이벤트·belief ◀───────────── ├─────────────────────────┤
  +GPS+신뢰도]             (원영상 아님)                    │ 엣지 NPU (Jetson Orin)  │
 [belief 히트맵]                                            │  · 사람 탐지기(EO+열)    │◀─ EO 짐벌 / LWIR 열화상
 [상태: 배터리/커버리지]                                     │  · PC_ObsModel 어댑터    │
                                                            └─────────────────────────┘
```

핵심 원칙 세 가지:
1. **비행 제어 루프는 온보드에 닫힌다.** Discord/LTE는 명령·감시용이지 비행-임계 루프가 아니다
   (인터넷 왕복 지연으로 드론을 조종하지 않는다).
2. **링크로는 관측만 건넌다** — 원영상이 아니라 탐지 이벤트(썸네일 수 KB)+belief 맵(576 float).
   우리 아키텍처(코어는 belief만 안다)가 그대로 대역폭 예산이 된다.
3. **안전은 링크·NPU와 독립.** 링크 끊김·NPU 죽음 → MCU의 RTA/geofence가 RTL(복귀)을 건다.

## 1. 센서 — 무엇을, 왜

우리 논문의 창발적 센서 선택(낮=EO, 밤=열)이 그대로 하드웨어가 된다. 각 센서는 코어에
`PC_ObsModel`(함수포인터 둘: `p_useful`·`precision`)로만 보인다 — 센서 교체 = 어댑터 교체.

| 센서 | 용도 | 근거 | 예 |
|---|---|---|---|
| **EO 짐벌 카메라 (RGB)** | 주간 1차 탐지 | 고해상·색 단서(의복), 저비용 | Sony 1/1.7" 20MP + 3축 짐벌 |
| **LWIR 열화상 (비냉각 마이크로볼로미터)** | 야간·연무·수관 틈 탐지 | 체온(~310K vs 배경)이 SAR 최강 단서, 조명 무관 | FLIR Boson 640(640×512) / Lepton 3.5(160×120, 저가) |
| **GNSS (가능하면 RTK)** | georegistration(격자↔실좌표) | red spot GPS를 격자에 앉힌다 | u-blox F9P(RTK, cm) 또는 M9N(~1-3m) |
| **IMU (가속+자이로+지자기)** | 자세, GNSS 드롭아웃 시 추측항법 | 짐벌 안정화·좌표 융합 | ICM-42688 + 지자기 |
| **1D 레이저 고도계 / 기압계** | AGL 고도 → 관측 footprint 스케일 | 고도가 `r_max`·픽셀↔미터를 정한다 | LightWare LW20 |
| (선택) **하방 depth/LiDAR** | 장애물·지형 회피 | 사람 탐지 아님, 항법 보조 | — |
| (선택, RF 배경) **mmWave 레이더** | 움직임·호흡 micro-Doppler | 정지·매몰 생존자(EO/열 안 보임)의 미세운동 | 60GHz FMCW |

**왜 레이더가 1차 탐지가 아닌가:** 소형 UAV SAR의 사람 탐지는 EO+열이 지배한다. mmWave는
매몰·정지 생존자의 호흡·미동 검출에 보조로 강하고, 우리 센서-불가지 틀에선 그냥 또 하나의
`PC_ObsModel`로 꽂힌다(코어 불변).

## 2. 온보드 연산 — perception/정책/안전 분담

우리 아키텍처의 "perception은 학습, 정책은 결정적, 안전은 봉투"가 곧 칩 분담이다.

| 조각 | 하드웨어 | 왜 |
|---|---|---|
| **사람 탐지기(EO+열)** = `PC_ObsModel` 뒤 | **엣지 NPU** (Jetson Orin Nano ~40 TOPS / Hailo-8) | 학습 모델은 MCU서 못 돈다. 여기가 유일한 학습 조각 |
| **정책 코어** `policy_core.c` (J 최대·τ·belief) | **비행 MCU** (STM32H7 / PX4 오토파일럿) | 힙·재귀 없음·결정적 → 베어메탈. 재컴파일로 이식 |
| **RTA/geofence** `pc_rta_filter` | **같은 MCU, 링크·NPU와 독립** | 안전은 학습·통신 밖. 링크 끊겨도 keep-out·RTL 성립 |
| 비행제어(자세·모터) | PX4/ArduPilot | 표준 |

탐지기 출력(탐지 여부·신뢰도·픽셀→월드 좌표) → `PC_ObsModel.p_useful` 실측값 → MCU 정책이
다음 웨이포인트 선택 → RTA가 geofence/keep-out 상한. **NPU가 죽어도 MCU 정책+RTA는 산다**
(관측이 안 들어오면 belief 갱신만 멈추고 안전 비행은 유지).

### 2.1 온보드 LLM 없음 — 자연어는 지상국이, 드론은 결정적 정책만

무거운 언어모델은 드론에 못 올린다(전력·열·지연·안전인증). 그래서 경계를 이렇게 긋는다.

| 어디서 | 무엇 | 어떻게 |
|---|---|---|
| **지상국(GCS=봇)** | 자연어 ↔ 구조 변환 | `sar/scenario.py` 가 "설악산 산불, 비, 조난자 2명" → {장소·조건·인원}. **필수(위치)가 없으면 되묻는다**(`sar/discord_cmd.py`) — 사람이 지명/좌표를 채울 때까지 임무를 안 짓는다 |
| **업링크** | 구조화 명령만 | 좌표·반경·긴급도 같은 **고정 슬롯**. 자유 문장을 드론에 안 보낸다 |
| **드론(MCU)** | 결정적 정책 | `policy_core.c` — 힙·재귀·부동소수 표 없이 J 최대화. 같은 입력 → 같은 행동(배포판 보장) |
| **다운링크** | 고정 문법 보고 | `sar/report.py` 의 SAR 무전 슬롯(WHO/WHAT/WHERE/STATUS/NEED/ACTION, MAYDAY>PAN-PAN>보통). 드론은 이 레코드만 채운다 — 문장 생성 모델 불필요 |

즉 **문장을 이해·생성하는 무거운 일은 전부 지상**에 두고, 공중에는 결정적 정책 + 고정 문법
메시지만 둔다. 링크가 끊겨도(3.3) 드론은 이미 받은 구조화 명령과 RTA 로 안전하게 마친다.

## 3. 통신 — 링크·프로토콜·대역폭

### 3.1 링크 계층

| 구간 | 링크 | 내용 | 비고 |
|---|---|---|---|
| UAV ↔ GCS (명령·텔레메트리) | **MAVLink over LTE/5G 모뎀** (BVLOS) 또는 900MHz/2.4GHz 라디오(가시선) | 웨이포인트·상태·탐지이벤트 | 광야는 셀 음영 → Iridium 위성 store-and-forward 백업 |
| UAV ↔ GCS (영상) | 온보드 저장(SD) + **주문형/이벤트형** 다운링크 | 탐지 썸네일만 실시간, 원본은 착륙 후 | 원영상 상시 스트리밍 안 함 |
| GCS ↔ 운용자 | **인터넷 → Discord 봇** | 명령 입력·탐지 카드·belief 맵 | 비-실시간, 감시·명령용 |

### 3.2 대역폭 예산 (왜 원영상을 안 보내나)

| 항목 | 크기/율 | 링크 부담 |
|---|---|---|
| 원본 4K 영상 스트림 | ~10-20 Mbps | BVLOS LTE서 불안정·과금·불필요 |
| **탐지 이벤트**(160×160 JPEG 썸네일+GPS+신뢰도) | ~5-15 KB/건 | 무시할 수준 |
| **belief 맵**(24×24 float, gzip) | ~1-2 KB/주기 | 무시할 수준 |
| 텔레메트리(MAVLink) | ~2-10 KB/s | 표준 |

관측(탐지·belief)만 링크를 건넌다 = 코어 설계가 곧 대역폭 규율. 대역폭이 SAR 광야에서
가장 귀한 자원이므로 이 분담이 실질적 이점이다.

### 3.3 실패 안전 (failsafe)

- **링크 끊김** → MCU가 정해진 시간 후 RTL(복귀) 또는 현 위치 선회. Discord/GCS 없이 성립.
- **GNSS 끊김** → IMU 추측항법 + 고도 유지, geofence 안에서.
- **NPU 죽음** → belief 갱신만 멈춤, 비행·RTA는 유지.
- **배터리 임계** → 무조건 RTL(정책·명령 위에서).

## 4. Discord 봇 = 수신기 (명령·다운링크 프로토콜)

저장소의 기존 `discord_bot_server.py` 패턴을 그대로 쓴다(봇이 명령 라우팅·승인 경계를 이미 가짐).

### 4.1 업링크 (운용자 → 봇 → GCS → UAV)

| 명령 | 뜻 | 승인 |
|---|---|---|
| `!search <lat,lon> [반경m] [긴급도]` | red spot 좌표로 능동탐색 시작. 반경→격자, 긴급도→β | **비행 명령 = 사람 승인 필수** |
| `!search <lat,lon>;<lat,lon>...` | red spot 여러 개 → **다봉 prior**(sim의 `--headroom` 국면과 동일) | 사람 승인 |
| `!abort` / `!rtl` / `!status` | 중단 / 복귀 / 상태 | abort·rtl은 즉시 |

**승인 경계:** 비행을 움직이는 명령은 이 저장소의 "승인은 공개 채널서 안 되고 주체는 사람"
규율(intent 게이트)을 그대로 따른다 — 아무나 드론을 날리지 못한다.

### 4.2 다운링크 (UAV → GCS → 봇 → Discord)

- **탐지 카드**: 썸네일 이미지 + `가능 생존자 @ (lat,lon), 신뢰도 0.xx, t=…` (봇이 채널에 게시).
- **belief 히트맵**: 주기적 이미지 — 수색 진행·수렴을 운용자가 눈으로 본다.
- **상태**: 배터리·위치·커버리지%·RTA 개입 수.

### 4.3 왜 Discord인가 (그리고 한계)

- 장점: 인증·채널·모바일 알림·이미지 게시가 공짜, 기존 봇 인프라 재사용.
- **한계(정직):** Discord는 **비행-임계 제어 채널이 아니다.** 명령·감시용이고, 비행 루프는
  온보드에 닫힌다. 인터넷 지연·끊김이 안전을 흔들면 안 되므로 §3.3 failsafe가 상위다.

## 5. 지도 + red spot → prior (georegistration)

- 운용자 지도 클릭 → (lat,lon). 반경 → 정사각 수색 구역. **24×24 격자**를 그 위에 앉힌다
  (셀 = 반경/12). 프라이어 = red spot 중심 가우시안 blob + floor = `sim.c`의 prior 그대로.
- **red spot 여러 개 → 다봉 prior** (이미 `sim.c --headroom`에 구현).
- 지도 타일(네이버/카카오/구글)은 **운용자 화면 표시용**일 뿐, 시스템 좌표는 GPS + 정사영상/
  DEM으로 georeference. **상용 지도 타일 재배포는 ToS 위반** — 표시에만 쓰고 저장·배포 안 함.

## 7. 정직한 한계·전제

1. **BVLOS 규제**: 가시선 밖 비행은 승인 필요(국내 특별비행승인). 데모·시험은 가시선/허가 구역.
2. **탐지기 품질이 병목**: 항공 사람 탐지는 SAR 전용 학습데이터(HERIDAL·SARD 등)로 학습해야
   쓸 만하다. 범용 보행자 탐지기는 top-down·소형 표적서 약하다(데모에서 실측해 정직히 보고).
3. **열화상 해상도**가 탐지 거리(고도·`r_max`)를 정한다 — 저가 Lepton은 근접만.
4. **셀 음영**: SAR 광야엔 LTE가 없을 수 있다 → 위성 백업 또는 store-and-forward.
5. **모델=진실 아님**: `p_useful`은 현장 캘리브(`CALIBRATION.md`)가 필요. 데모는 실제 탐지기
   출력으로 `p_useful`을 실측해 이 간극을 좁힌다(가짜 곡선 대체).
